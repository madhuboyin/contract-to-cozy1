## Shared-renderer and custom-renderer observations

Every operation uses the shared block registry. The main specialization seam is `GROUPED_LIST`: `GroupedListBlock.tsx` imports domain-specific result components and also selects declared patterns such as status accordion, shelves, deck, room map, choice grid, and budget breakdown. A “custom renderer” in this inventory therefore means a sub-renderer selected within a shared block, not a separate operation-owned top-level renderer.

## Inconsistencies and limitations

- Static inspection finds some operations whose adapter registration is not a simple one-line literal; these are marked Unverified rather than Stub. Startup validation is the authority for actual coverage.
- Allowed block types are a safety envelope, not proof every listed block is emitted on every branch.
- User-action and follow-up support vary by branch, entity state, role, and operational policy.
- The homeowner-job mapping is analytical and can legitimately be multi-job for commands and cross-domain operations.
